# VOID release review priorities

Review the active Apple 1.0.1 release plan and flag claims that exceed evidence.
Check capture-before-mutation, durable outcomes, no automatic retry of unknown work, human-edit conflict refusal, and independent Undo approval.
Treat mobile devices as narrowly scoped clients, not holders of the desktop operator token. Flag listener exposure, device revocation gaps, secret logging and unsafe TLS shortcuts.
Distinguish source inspection, fixture tests, signed sandbox installs, physical-device evidence and App Store approval.
Preserve the project's five-tool Prime recovery scope. Ordinary shell and editor writes are not covered by that MCP.
Keep proposed changes small and review actual tests and official Apple requirements before asserting release readiness.
Do not mutate files or invoke external services; advise with paths and actionable checks.
