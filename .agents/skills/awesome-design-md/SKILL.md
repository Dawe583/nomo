# Awesome Design reference library

Use this skill when a UI needs stronger visual direction, information hierarchy, interaction patterns, or a design-system reference.

1. Inspect the current product and constraints before choosing a reference.
2. Choose one or two relevant references from `references/design-md/` (for example `apple`, `linear.app`, `supabase`, `stripe`, `vercel`, `notion`, `raycast`, or `nvidia`).
3. Read the selected `DESIGN.md` and, when useful, its `README.md`.
4. Translate principles into the project's own tokens, components, content, accessibility rules, and brand; do not reproduce logos, copy, or proprietary assets.
5. State which principles were borrowed and verify the result against the existing product rather than adding decorative complexity.
