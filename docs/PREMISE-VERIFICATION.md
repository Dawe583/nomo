# Historical premise verification: earlier VOID direction

> Historical independent check of the earlier VOID recovery-first strategy,
> written 2026-09-26. The source report was retired on 2026-10-09. This does not
> validate the current NOMO market direction. Current market evidence and the
> customer qualification test are in the NOMO MVP spec.

Written 2026-09-26 against the working tree at `/Users/dawe/Developer/Claude-Projects/VOID`.
Subject: `docs/VOID-FUTURE-DIRECTION.md` (1202 lines, authored the same day).

This document is a check on that report, not a restatement of it. Where the report is
right it is right for a reason I could reproduce; where it is wrong I give the
counter-evidence. Where I could not check something, I say so rather than guessing.

**Method and its limits.** Local claims were checked by reading source, by reproducing
the report's own greps, and by running a throwaway harness against the pinned MCP SDK
to observe the version the server actually answers. External claims were checked by
fetching primary sources directly. General web search was rate-limited for this entire
session (Codex 429; Google, Startpage, DuckDuckGo, Ecosia and Mojeek all returned bot
walls), so external findings rest on the vendors' own pages and the GitHub API rather
than on third-party summaries. No build or test suite was run, as instructed. No
credential, keychain secret or signing private material was read; signing identities
were checked for *existence* only.

## What this means for "an AI agentic reverse tool for security"

Stated plainly, and without recommending a course of action.

**The gap the report names is real, total, and correctly named.** This is not a project
with a weak reverse-engineering capability. It is a project with no reverse-engineering
capability of any kind — no binary parsing, no disassembly, no decompilation, no symbolic
execution, no protocol reconstruction, no fuzzing, no native bridging. I searched
independently and found nothing. The framing in the two "reverse" documents has always
meant *reversing an operation*, and their own titles and work-package lists say so in
plain language. If the stated goal is to *be* an agentic reverse tool for security, then
that capability does not exist in this repository in any form.

**But the report is wrong about what is being undervalued, in the direction that
matters.** Three things it treats as thin are substantial:

1. **Byte-level inversion of non-filesystem state already works.** S3 object bodies are
   captured as opaque byte sequences, digested, and restored byte-exactly — verified by a
   cross-layer test, not just a unit test. "No patching" is too strong: this is
   byte-exact before-image and restore of an effect that is not a file.
2. **The reversibility registry is a 268-entry, 48-service knowledge base** with an
   effect class, reversibility class, described inverse, validity window and
   preconditions per entry. The report cites the file and never counts it. Both
   numbers were measured on 2026-09-29 against `packages/registry/src/registry.ts`:
   268 is the length of `registry`, and 48 is the length of `registryVendors()`,
   which is the number of distinct `vendor` values across those entries. The 54
   services this paragraph used to claim is not the count of anything in the tree,
   and how many of the 268 are executable is a different question with a
   different denominator; the dated correction for both is in the errata at the
   end of `docs/ROADMAP-2026-Q4.md`. Whether it is *executable* is a different
   question from whether it is *knowledge*, and the knowledge is the part that
   took the work.
3. **Three competing projects ship a real hash chain and two of those also sign.** The
   report is right that signing is no longer a differentiator, and the evidence is
   stronger than its table shows: Prismor, AgentLock and Microsoft AGT all do it, and
   Prismor's is the closest external analogue to VOID's own design.

**And the two places the report is most confidently wrong both understate the problem
rather than overstate it, which is worth noting because it cuts against the report's own
conclusions.** The MCP gap is *one* revision behind (`2025-11-25`), not three, and VOID's
server echoes the client's requested version rather than pinning a stale one — so a
conforming modern client would fall back to `initialize` and connect, degrading rather
than failing. The signing cost is $0, not $99/year: the live data-loss-shaped keychain
incident is caused by an *unstable* identity, and stability is free. $99/year buys
Developer ID, which buys notarisation and distribution trust — a real and separate thing,
but not the fix for the bug the report calls "the single most damaging thing currently
wrong with the project."

**One external claim does not survive contact with its source.** The ProjectDiscovery
quote is verbatim, the speaker and venue check out against the conference's own
