# NOMO × YC: three-idea execution playbook

**Status:** founder working hypothesis; customer demand and willingness to pay are unvalidated. **Market sequence:** Czechia first, EU after evidence. **Scope:** cross-industry discovery; no segment is preselected.

## One product sequence, not three parallel products

### 1. The $15-an-Hour Expert — first customer outcome

Help a worker complete one repeated expert task using approved sources, visible uncertainty, and human escalation. Select the task from recent customer cases. Finance is only one candidate. First run a concierge evaluation against the current process; build customer UI only after the evaluation shows a useful and safe result.

**Entry evidence:** buyer, operator, and domain expert are identifiable; a recent case can be discussed; the customer can provide an authorized sample; the current process has a measurable baseline; the buyer will discuss a paid, bounded pilot.

**Pilot boundary:** read-only assistance; one workflow; one approved source set; no silent write-back; explicit abstention and escalation; agreed sample, rubric, support limit, retention, and deletion.

### 2. Own Your Intelligence — later improvement loop

Capture expert-approved corrections and governed source versions as evaluation data. Compare baseline, retrieval, rules, and available models before considering training. Propose changes for human approval. Do not imply that a customer model is automatically improved just because usage data exists.

**Entry evidence:** repeated use creates cases with permission; expert corrections are consistent; versioned holdout evaluation shows a measurable improvement beyond retrieval and rules; the buyer values this improvement.

### 3. AI for the Air-Gapped Economy — deployment branch

Treat deployment as a customer requirement, not the opening product. Distinguish managed cloud, customer cloud, on-premises with controlled egress, and fully disconnected air-gap. Each boundary has different operations, update, support, and security costs.

**Entry evidence:** written egress requirement; named security owner; target hardware; offline update and recovery design; funded implementation and continuing support.

## NOMO integration map

1. **Case and scope:** capture one task and its allowed input and output.
2. **Identity and policy:** authorize the operator, agent, source set, model route, and permitted operations.
3. **Harness:** execute a bounded, observable run; record model and policy versions; disallow silent cloud fallback; support abstention.
4. **Ledger:** retain evidence references, output, uncertainty, human decision, correction, duration, and outcome under agreed retention.
5. **Human approval:** keep pilot read-only; introduce one idempotent write only if the proven workflow requires it and NOMO supports approval, rollback, and audit.

The NOMO first-live release is a technical prerequisite, not proof of demand. Verify each reusable contract in the shipped release before integrating it. Do not present the planned fleet runtime as production-ready.

## Czech-first customer motion

1. Ask the available owner/CFO for a neutral interview about the last specific task. Do not pitch savings or a predetermined finance workflow.
2. Use LeadsPicker to create a manually qualified research list. Record contact provenance and a lawful basis/channel before any commercial outreach. Public or inferred business contacts alone do not establish permission to send a marketing message.
3. Compare recent cases across candidate workflows and industries. Seek operator, buyer, and expert evidence, plus authorized samples and the present alternative.
4. Run a concierge evaluation with a small approved sample and agreed rubric.
5. Offer a paid read-only pilot only after comparison with baseline. Agree price with the buyer; do not infer it from market size.
6. Expand to a second company in the same workflow before generalizing across industries.

## Decision rule

Continue only when there is a repeated task, authorized case access, measurable value versus the current alternative, acceptable quality and safety, and a buyer willing to fund a bounded pilot. Change the hypothesis or stop when these conditions do not hold. Keep all metrics and commercial claims labeled as hypotheses until observed.
