## What this session built

### The hosted NOMO MCP, derived instead of hand-maintained

The endpoint previously carried two tools and a **hand-maintained list of eight
recovery tool names** in `apps/appwrite-mcp/src/app.py`. Nothing compared that
list to `packages/cli/src/recovery-mcp.ts`, so it would have kept publishing
names that no longer existed, with no test failing.

`apps/appwrite-mcp/src/appwrite_mcp/nomo_data.py` now reads every published
fact from the source tree: the registry from
`packages/registry/src/registry.ts`, the local tool names, arguments and
`readOnlyHint` from `packages/cli/src/recovery-mcp.ts`, the CLI surface from
`packages/cli/src/dispatch.ts`. `app.py` publishes six tools over it.

Measured from the live tree, registry `2026.09.2`: **268 operations, 491
preconditions, 48 vendors, 170 surfaces**; classes `r0` 57, `r1` 101, `r2` 156,
`r3` 177.

### The snapshot, and the gate that keeps it honest

A deployed Appwrite function receives a tarball, not a checkout, so it cannot
read the tree. `nomo_snapshot.json` travels with it, generated by
`apps/appwrite-mcp/scripts/generate-snapshot.py` from
`appwrite_mcp.snapshot_builder`, which lives in the function package so the
gate and the generator cannot drift apart. A test compares the committed
snapshot against a fresh build and fails if they differ, so a stale snapshot
fails the gate rather than being published.

### Appwrite resources, provisioned and seeded live

`cloud/appwrite.mjs` gained three tables and their indexes to the manifest.
`cloud/seed-appwrite.mjs` fills them from the same source. Both were run
against the live project:

| Table | Rows | Indexes |
| --- | ---: | ---: |
| `registry_operations` | 268 | 4 |
| `registry_cases` | 491 | 2 |
| `mcp_tools` | 6 | 1 |

All have `rowSecurity` and `documentSecurity` on and no row-level permissions,
so a client SDK cannot read them. Verified live: an indexed lookup of
`operation_id = aws.s3.object.put` resolves to exactly one row and its three
preconditions come back with the classes, inverses and windows the source
declares; class counts read back from the `tone` index match the source exactly.

Three findings from the live API that cost time and are worth keeping:

- **A row id is capped at 36 characters** and registry ids run to 39, so
  `rowIdFor` uses a SHA-256 digest rather than a truncation. A truncation
  collides silently, and is not stable under growth.
- **An upsert takes `{ data, permissions }`,** not a flat body. A flat body is
  refused with `row_missing_payload`, which reads like a validation failure
  about the row rather than about the envelope.
- **`queries` is `queries[N]` = one compact JSON object.** Not a JSON array of
  objects, not a bracketed param. Found by measurement.

**A signed ledger is deliberately not published.** A ledger's value is that it
is signed and append-only; a hosted unsigned copy would be a second thing to
argue about. The registry is public reference data, a ledger is evidence, and
the seeder keeps them apart.

## The blocker, measured rather than assumed

**The MCP function has no registered public domain, so it has no reachable
URL.**

```
POST https://6abbae3e000f6f24ce2a.fra.appwrite.run
  -> 404 {"type":"router_rule_not_found"}
GET  /v1/functions/6abbae3e000f6f24ce2a/domains   (with the project API key)
  -> 404, HTML: the domain routes refuse that key
```

Adding a domain is a console action. The project API key in `.env.local` cannot
read or create function domains, which was measured, not read off a doc page.
Until a person does it there is no hosted MCP URL, nothing to submit to
`registry.modelcontextprotocol.io`, and no remote verification. The step is
recorded in `appwriteManifest.manualSteps` so it is visible in the manifest and
not only in prose.

## What is still red, and why

Nothing in the design-source gates. All three are green, and closing them is
written up in `docs/DESIGN-TOKEN-MIGRATION.md`.

What happened there is worth stating plainly, because the first plan was wrong.
The gates found 10 colour literals and 59 radius literals, and the tempting
move was to map each onto the nearest existing token. That would have made the
gate green and changed how about twenty components look, on a surface no
browser in that session had opened. The opposite was true and much cheaper:
every conversion maps a value to a token holding that **same** value, so nothing
can change. Where a value had no token, the token was added, seven radius
roles, three syntax roles with six measured contrast pairs, and a scrim role in
its own section because a veil is not a drop shadow.

The measurement that made the syntax roles safe to add: all six highlight.js
colours already cleared 4.5:1 against both surfaces in both appearances, at
6.23:1 worst. Nothing was tuned; the document was behind the code.

## Also fixed, from the failures that were already on arrival

**The hit-target gate.** `scripts/src/tokenise-hit-targets.py` replaced 52
hand-written `44px` and `28px` declarations with `var(--control-touch)` and
`var(--control-macos)`. Both tokens hold the identical value, so the computed
style cannot change, that is why this one was safe to automate and the radius
and colour ones were not. `--check` fails rather than writes, and a new test
asserts the tokens the stylesheet reads are the ones the document declares.

**The permission-authority class.** `apps/control-plane/ui/src/permission-mode.tsx`
was missing the class its own test asserts on; the two non-interactive notices
now carry `muted permission-authority`.

**The dead-path inventory.** `mobile.css` and `ascii.css` were merged into
`styles.css` while three documents still named them. They are now in
`scripts/src/doc-truth.test.mjs` INVENTORY with the reason, which is what that
list is for.

**Historical hosted job time budget.** The former `hosted-mcp` job declared a
15-minute timeout for steps totalling 20. It was raised to 25 before all hosted
workflows were later retired. This is historical evidence only.

**Three browser findings, which were not this session's work.** The
`ui-layout` gate reported a 36px-wide command trigger, a transcript squeezed
to 184px and 189px where it requires 200, and it did so against `main` at HEAD
with the token migration reverted, verified by running the gate twice, once on
HEAD's stylesheets and once on the migrated ones, with identical results in
both. They were real defects and are fixed:

- `.command-trigger` had a 44px height and a 36px width. It is a standalone
  composer icon next to `chat-options-trigger`, so `min-width` now reads
  `--control-touch` like its neighbour.
- `.composer-notices` was allowed 18% of the viewport, which at 568px tall is
  102px, and the transcript got what was left. The ceiling is now 14% and 96px,
  which leaves the conversation readable with a long draft, an attachment and a
  tool row all present at once, the three conditions the gate stacks.

**One conversion that was wrong and is now right.** `border-radius: 1px` on the
2px-wide stream caret was mapped to `--radius-capsule`, because the script read
`999px` out of a mapping table and the caret's original value was not in it. The
rendered result is the same, 1px and 999px on a 2px element are both a pill , 
but the role was a lie about what the value is, and the role is what the next
reader trusts. It reads `--radius-hairline` now. The cause was a script I wrote
and then deleted, so the correction is in the tree and not in the tool.

## Two production bugs found by asking what a deploy actually gets

Both were invisible to the offline suite, because the offline suite runs from
a checkout and a deployed Appwrite function does not. `scripts/src/` had the
answer for the registry and not for the other two readers, so a deployed build
answered `nomo_registry_summary` correctly and `nomo_cli_commands` with nothing,
having passed every test in the repository. The new
`apps/appwrite-mcp/scripts/verify-deploy-shape.py` extracts the deploy tarball
into a scratch directory with no `packages/` anywhere near it and asks all six
tools the same questions, and it is in CI for the reason the contract tests are
not enough on their own.

The second is narrower and was found by writing the test that had been missing:
a 403 from the bucket on the restore `PUT` was reported as `internal_error`,
while the same status from anywhere else in the same call was reported as
`permission_denied`. Both sites now read the status through one helper, which
also picks up a bare `statusCode` and not only the AWS SDK's `$metadata`.

Two guards in the S3 restore are now pinned by
`packages/connectors/src/s3/apply-guard.test.ts` rather than left to the
existing tests: the `ifNoneMatch: "*"` that makes restoring into a key a
concurrent writer just created refuse instead of overwrite, and the invariant
that no refusal path can emit a receipt, since the receipt is the only evidence
a restore produced.

`packages/ledger/src/reversal-boundary.test.ts` does the same for the reversal
rule, including the case that matters most: a whole file re-chained and re-signed
by an attacker with their own key is still rejected, because the false reversal
has no witness. The honest half is asserted too: a rewrite that keeps the
reversal truthful verifies, so the check is a rule and not a blanket refusal.

## A 2px regression the token migration introduced

The mobile dialog's top corners were `24px` at HEAD and became
`var(--radius-full)`, which is 22px. A 2px change on a full-width bottom sheet
is visible, and the migration document claims every conversion maps a value to a
token holding that same value, so this one contradicted its own stated rule. It
was the same fall-through the caret hit: the mapping table had no role for 24px,
so the nearest one was used.

Fixed by adding the role rather than by moving the value, because 22px is the
token's real content and three other surfaces depend on it. `--radius-sheetcap`
is 24px, and the mobile dialog is the only radius in the stylesheet that used
24px at all. The role is one lowercase word because the Swift token generator
refuses a hyphenated key, which it caught by throwing rather than by emitting
something that would not compile.
